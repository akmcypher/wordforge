# Phase 1A: durable identity and grouped transactions

> **For agentic workers:** Use executing-plans to implement these tasks in order.
> Implemented in 0.4.1; see CURRENT_STATUS.md and phase1a evidence.

**Goal:** Persist existing paragraph identity across native saves and introduce a
usable grouped command boundary without replacing the working flat model yet.
**Architecture:** Document-scoped uint64 IDs and monotonic allocation; native v2
writer with v1/v2 readers; candidate transactions with one history publication.
Retain all current text/layout/desktop APIs while the structured tree follows in1B.
**Stack:** Existing C++20 core, pugixml, GoogleTest, Qt integration tests.
**Spec:** `../../ENGINEERING_DIRECTIVE.md`, roadmap Phase 1A and current handoff.

## Constraints and review focus

- IDs are nonzero uint64, unique within a document; `nextId` exceeds every live
  node and is never reused after undo branching in the same document session.
- An ID is not a serialized vector index. Cross-document resource/anchor identity
  follows in1B; do not claim it is solved by paragraph IDs alone.
- All native v1 text/styles/page settings stay readable. No loss-based migration.
- Integer parsing must not pass through double: test IDs above2^53, leading signs,
  zero, overflow, trailing characters, duplicates and exhausted allocation.
- Failed transactions/imports preserve document, selection, typing style, both
  history stacks and revision behavior. Invalid operations never publish changes.
- Full import validation is separate from changed-node editing validation. Record
  any initial O(n) grouped-diff cost; do not move it onto every single keystroke.

## Task 1 — Shared validation and stable allocation

Modify `core/document/document.*`; add `validation.*` if needed. Tests in
`tests/unit/document_test.cpp` and `format_test.cpp`.

Interface: `void validateDocument(const Document&)` for persistence/reset boundaries;
`Document::allocateId() -> uint64_t` for every new paragraph. Keep existing IDs,
move raw `nextId++` callers behind that allocator, and reject exhausted allocation
before changing model/history. Keep per-command validation localized.

## Task 2 — Native v2 schema and v1 migration

Modify `core/formats/native.*`; add `docs/WFG_SCHEMA.md`, legacy fixtures and tests.
Interfaces remain `parseNative(string)->Document`, `serializeNative(Document)->string`.

Schema decision: v2 retains existing root/paragraph/run formatting attributes and
adds required root `nextId` and paragraph `id`. Serialize uint64 exactly. New writer
emits version2; reader dispatches version1/version2. V1 generates IDs in document
order once, then produces valid v2 allocator state. V2 must not regenerate IDs.
Revision counters are in-session invalidation state, not durable edit history.

- [x] Add v1 golden fixtures covering whitespace/CDATA/Unicode/styles/lists/breaks.
- [x] Add v2 sparse/>2^53 IDs, reordered paragraphs, malformed allocator/duplicates,

- [x] Implement dispatch/migration/schema checks, keeping v1 parsing exercised.
- [x] Verify recovery reads old snapshots and writes new snapshots, atomic save,
  DOCX export and desktop open/save still work. Old binaries may reject version2;

## Task 3 — Grouped command transaction and change set

Modify `core/document/document.*`, add `transactions.*` only if responsibility
benefits. Interface: `ChangeSet Editor::transact(function<void(Editor&)>)`;
`ChangeSet` carries before/after document revision, inserted/removed/changed IDs
and page-geometry change. No Qt or renderer types. Nested transactions/history
operations/reset inside a callback are rejected explicitly in this first slice.

## Acceptance and subsequent work

Phase 1A exits when legacy documents remain readable, identity persists, allocation
does not collide/reuse after undo branching, and an actual composite editor command
uses an atomic grouped transaction with tested rollback and change reporting.
This is still **not** the full structured model. Next:1B typed nodes/resources and
stable anchors,1C semantic styles/efficient versions, then2A page checkpoints.

Execution ruling: migration and grouped transactions ship in one reviewed checkpoint because allocator high-water and rollback invariants span both. The model benchmark establishes a new baseline; no historical speedup or persistent-storage claim is made. Scope remains 1A; typed tree/resources/anchors are next in 1B.
