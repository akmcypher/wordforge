# DOCX interoperability implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Open ordinary DOCX text documents and export the supported native formatting as real OOXML ZIP packages.
**Architecture:** Bounded in-memory OPC ZIP transport using libzip; pugixml maps OOXML into the existing model. Imported files open as unsaved copies. Unsupported content is reported and never silently overwrites its source.
**Tech Stack:** C++20, libzip >=1.7, pugixml, existing Qt6 UI/model/renderer.
**Spec:** This document is the scoped interoperability specification; it does not promise Word parity.

## Global constraints

- Preserve Unicode, whitespace, supported run/paragraph formatting, page geometry and lists.
- Resolve main document and related styles/numbering via package relationships; never fetch external URLs.
- Bound compressed input, individual parts, aggregate expansion and entry count; reject duplicate/traversing part names and DTDs.
- Detect unsupported content. Tables, drawings, fields, revisions, headers/footers and multi-section layout are not claimed as implemented.
- No Co-authored-by trailers, published-history rewriting or unrelated Meridian changes.

## Review focus

- Common Word documents inherit styles: test document defaults, basedOn and direct overrides.
- Namespace prefixes can change: test non-w prefix, strict namespace and wrong-namespace lookalikes.
- Lists can restart/change format: preserve supported contiguous decimal/bullet semantics; warn on unsupported numbering.
- Malformed/expanding ZIP/XML must fail before changing the open document.
- DOCX import must be a copy and failed export must preserve existing bytes and dirty state.
