Better Word compatibility: table borders and shading, indents and justified text, Word Strict
and template files, and text files in any language's encoding. Measured against Microsoft
Word itself.

## Downloads

**Windows 10 (1903+) and Windows 11**

* `Wordforge-0.6.7-windows-x64-setup.exe` — installer for most PCs
* `Wordforge-0.6.7-windows-arm64-setup.exe` — installer for Arm PCs (Snapdragon and similar)

The installer needs no administrator rights. It adds a Start menu entry and an
uninstaller (Settings → Apps), opens `.wfg` files in Wordforge and adds Wordforge to
"Open with" for `.docx` and `.txt`.

Portable versions, nothing to install: `Wordforge-0.6.7-windows-x64.zip` and
`Wordforge-0.6.7-windows-arm64.zip`. Unzip the whole folder, then run `Wordforge.exe`.

The builds are not code-signed yet, so SmartScreen may ask you to confirm the first
launch (More info → Run anyway). Checksums are in `SHA256SUMS.txt`.

**Ubuntu (amd64, arm64)**: `sudo snap install wordforge` (https://snapcraft.io/wordforge)

## Changes since 0.6.6

* **Table borders and shading.** Format → Table → Borders… sets the width (or no
  borders) and colour of a table's lines; Cell shading… fills the selected cells. Both
  follow row, column and merge edits and travel to and from Word. Before this, Word cell
  shading was dropped when opening.
* **Indents and justified text.** The Format panel gains First line (negative values make
  a hanging indent) and Right indent; Justify (Ctrl+J) spreads lines to both margins.
  All of these open from and save to Word. Word lists keep their indentation, and nested
  list levels now appear indented.
* **More Word files open.** Word's "Strict Open XML" documents, macro-enabled documents
  (`.docm`, macros removed) and templates (`.dotx`, `.dotm`) open as editable copies.
* **Text files in any encoding.** Besides UTF-8, Wordforge now reads UTF-16 and UTF-32 and
  detects legacy encodings: Shift_JIS, EUC-JP, GB18030, Big5, EUC-KR, Windows code pages
  for Western, Central European, Cyrillic, Greek, Turkish, Hebrew, Arabic and Thai, and
  KOI8-R. Before this, such files opened garbled.
* **Fixes from testing with Microsoft Word.** Word page breaks and next-page section
  breaks now start new pages; Word's theme fonts (such as Aptos) no longer become Arial;
  Word's automatic text colour no longer turns dark blue-grey.

How this was measured: Word built 114 test documents, Wordforge opened and saved each,
and Word compared the results. Paragraph formatting and page counts now match in all of
them and the score rose from 79 to 97 out of 100. A second check saved one document with
text in 23 languages in every format Word offers: every format Wordforge opens kept all
its text. Details: docs/WORD_FIDELITY.md and docs/FORMAT_COMPATIBILITY.md.

Documents with table borders or shading, first-line or right indents or justified text
are saved as WFG11, which 0.6.6 cannot open. Other documents keep their earlier format.

## Known limitations

* Word 97–2003 `.doc`, RTF and OpenDocument `.odt` files do not open yet.
* Word heading theme colours, endnotes, fields (such as a table of contents), hyperlink
  targets and section settings (orientation, columns) are lost, with a warning when you
  open the file.
* Nested list levels are indented but use one marker style. Borders are one width and
  colour per table.
* LibreOffice has not been tested yet; the checks above used Microsoft Word.
* Encoding detection can guess wrong for very short legacy text files; there is no
  manual encoding choice yet.
* Tracked changes cover typed and deleted text only; word count, find and plain-text
  export still include deleted text.
* Visual caret movement through mixed-direction text and screen-reader support are
  incomplete.
* Windows packages are not code-signed and have not been tested on a fresh Windows 10
  installation. The Snap's strict confinement is tested headless in CI, not yet
  interactively on a real Ubuntu desktop.

Please report problems at https://github.com/akmcypher/wordforge/issues.
